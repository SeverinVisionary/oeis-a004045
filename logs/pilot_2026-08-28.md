### One correction to session 1's wall-clock

Session 1 reported HiGHS rung 60 as taking 1312.2 s. This session measured
**112.6 s for the identical search** — the node count is 15 246 both times, so
it is the same tree, explored at 11.6× the speed. The difference is host
contention, not compute. Session 1's derived claim of "**≥143×/rung** in time,
against the 13–28× the node counts suggested" was therefore a contention
artifact. Measured seconds per node are in fact close to flat:

```
             rung 59    rung 60    rung 61    rung 62
HiGHS       0.0090     0.0074     0.0068     0.0059   s/node
SCIP        0.0152     0.0084     0.0063     0.0055   s/node
```

Per-node cost is not exploding, so **node count converts to wall-clock
reliably** and is the right currency for the extrapolation.

### Node growth per rung

```
          57->58   58->59   59->60   60->61
HiGHS       28x     43.5x     12.5x    >208.7x
SCIP        15x     13.1x    175.3x     >99.1x
```

The rung-61 figures are **lower bounds**: both solvers were cut off mid-tree.
The two solvers disagree sharply about *where* the jump happens (SCIP's blow-up
is at rung 60, HiGHS's at rung 61), so no single per-rung ratio is supported by
both. What both agree on is that the ratio is not constant and is far above the
13–30× that rungs 57–59 alone suggested.

**Rung 62's node count carries no information about rung 62's difficulty.**
Both 61 and 62 were truncated at the same 6 h wall-clock with similar per-node
costs, so their node counts are necessarily similar (3.2M vs 3.7M). It would be
an error to read that near-equality as "rung 62 is barely harder than rung 61".

## Prescribed automorphisms — the sweep is now complete

`prescribed.py` was instrumented first, because as written it dropped every
non-optimal orbit-ILP silently, conflating two different outcomes:

* `Infeasible` — a genuine negative, no `G`-invariant covering of size `<= 64`;
* `Time limit reached` — the instance is simply **unresolved**.

Run to completion (`logs/prescribed_cyclic_sweep_full.log`, 5792 s):

```
groups solved: 742
non-optimal instances: {'Infeasible': 76, 'Time limit reached': 227}
UNRESOLVED: 227
BEST 64  cycle type (8,) t=1 orbits=16
size distribution over groups: [(64, 439)]
```

So **227 of 742 instances (31%) were undecided** at the 20 s limit — and they
are the ones with the largest orbit counts, i.e. the *least* symmetric groups,
exactly where a code below 64 would survive. Session 1's negative result was
therefore not exhaustive even over the cycle types it reported as finished.

The 227 were re-solved with `prescribed_followup.py`, asking the question that
actually matters — **is there a `G`-invariant covering of size `<= 63`?** — which
is both the research question and cheaper than proving optimality at 64:

```
round 1, 60 s each,   4 shards:  157 Infeasible,  70 still open,  0 witnesses   (8491 s total)
round 2, 1200 s each, 4 shards:   70 Infeasible,   0 still open,  0 witnesses   (8119 s total)
```

All 227 are now closed, every one `Infeasible` at `<= 63`.

`prescribed_filter_audit.py` then pinned down what the sweep's
`8 <= K <= 140` orbit-count filter silently excludes — 4 of 746 `(pi, t)`
classes, all with `t = 0`:

```
total (pi,t) pairs: 746      passed filter: 742      excluded: 4
  (2,2,2,1,1)       t=0  orbits=144
  (2,2,1,1,1,1)     t=0  orbits=160
  (2,1,1,1,1,1,1)   t=0  orbits=192
  (1,1,1,1,1,1,1,1) t=0  orbits=256   <- identity: the unrestricted problem
```

The three non-identity ones are real symmetry classes, and
`prescribed_excluded.py` settled all three at `ub = 63`:

```
(2,2,2,1,1)     t=0 orbits=144: Infeasible  [182s]
(2,2,1,1,1,1)   t=0 orbits=160: Infeasible  [298s]
(2,1,1,1,1,1,1) t=0 orbits=192: Infeasible  [538s]
```

**Result: 745 of the 746 cyclic `(pi, t)` classes admit no `G`-invariant double
covering of size `<= 63`.** The one exception is the identity with `t = 0`,
which is the unrestricted 256-variable problem itself — not a symmetry
restriction, and precisely the rung-63 question the ladder is climbing.

This is a complete negative result over the cyclic prescribed-automorphism
stratum, and it strengthens session 1's incomplete version. It says a `<= 63`
witness, if one exists, has trivial cyclic automorphism group. It says nothing
about non-cyclic subgroups, which remain unswept.

Best invariant code found is still 64 (8-cycle, `t = e1`, 16 orbits),
`logs/presc_best_code.json`, re-checked by `verify.py`:
